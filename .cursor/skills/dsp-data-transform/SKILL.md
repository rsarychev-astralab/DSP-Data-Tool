# Преобразование данных DSP в целевой шаблон

## Цель

Получить файл `.xlsx`, совместимый с шаблоном `Шаблон загрузки данных от DSP (2).xlsx`:
- **Строка 1** — заголовки колонок (копировать из шаблона без изменений)
- **Строка 2** — описания полей (копировать из шаблона без изменений)
- **Строка 3+** — данные партнёра, приведённые к формату шаблона

Эталон структуры и правил полей — [reference.md](reference.md).

## Два принципа

### 1. Преобразуй данные, где это следует из инструкции

Задача агента — **не просто скопировать файл**, а привести каждую строку к формату шаблона. Если во входе есть значение и для него описан маппинг или правило нормализации — **примени преобразование обязательно**.

### 2. Skip пустых ячеек

Если поле **пусто** (`null`, пустая строка, только пробелы) или **источник не определён** — **skip**: не преобразовывай и не записывай в выходной файл. Не подставляй defaults и не угадывай.

Ячейка считается пустой, если после `strip()` строка пустая или значение `None` / `NaN`.

---

## Skip пустых ячеек

Правило применяется **на каждом этапе** — к каждому полю отдельно, строка при этом обрабатывается дальше.

| Этап | Пустое значение → skip |
|------|------------------------|
| Чтение входа | Не добавлять ключ в `record` |
| Нормализация | Не вызывать правила преобразования |
| Запись в `.xlsx` | Не вызывать `ws.cell(...)` — ячейка остаётся truly empty |

**Запрещено при skip:** писать `""`, `" "`, `None`, `N/A`, `-`, `0` как заглушку.

```python
def has_value(val):
    if val is None:
        return False
    if isinstance(val, float) and val != val:  # NaN
        return False
    return str(val).strip() != ""
```

---

## Что агент обязан преобразовывать

| Ситуация | Действие |
|----------|----------|
| Колонка партнёра совпадает с синонимом из таблицы маппинга | Записать в соответствующую колонку шаблона A–S |
| `advertiser_inn` / `customer_inn` | → колонка I (`customer_inn`) |
| `contractor_inn` / `publisher_inn` | → колонка N (`contractor_inn`) |
| Значение справочника на русском или в другом регистре | Нормализовать к допустимому значению из [reference.md](reference.md) |
| «с НДС» / «без НДС» / `with_vat` | → `yes` / `no` в колонке Q |
| Дата в любом распознаваемом формате | Привести к единому формату (C) |
| Число с пробелами, запятой, символом валюты | Очистить и записать числом (R, S) |
| ERID внутри URL | Извлечь токен → колонка A |
| Одни и те же данные договора / исполнителя в каждой строке входа | Перенести в каждую строку выхода |
| Константы передал пользователь (номер договора, ИНН DSP и т.д.) | Подставить во **все** строки |

**Не преобразовывай (skip):** поле пустое; поле отсутствует во входе; маппинг неоднозначен; значение не из справочника и нет точного соответствия.

---

## Главное правило: не придумывай значения

Если поле **пусто во входных данных** или **источник не указан пользователем** — **skip**: ячейка в выходном файле остаётся пустой.

**Запрещено:**
- подставлять значения по умолчанию (`N/A`, `-`, `0`, `Unknown`, `LegalPerson` и т.п.);
- выводить тип контрагента, ОКСМ, НДС, договор и другие поля «по догадке»;
- дублировать одно поле в другое без явного маппинга (например, ИНН заказчика → ИНН исполнителя);
- заполнять поле константой из договора, если пользователь **не передал** эту константу явно.

**Разрешено:**
- нормализовать **уже существующее** значение (формат даты, регистр справочника, `yes`/`no`);
- извлекать ERID из URL, если во входе URL — это не «придумывание», а парсинг;
- оставлять строку с пустыми обязательными полями и зафиксировать это в отчёте / ошибках валидации.

Пустая ячейка в `.xlsx` = ячейка **не записана** (skip write). Не пустая строка и не заглушка.

## Рабочий процесс

```
- [ ] 1. Изучить входной файл (формат, колонки, примеры строк)
- [ ] 2. Составить маппинг: входная колонка → колонка шаблона
- [ ] 3. Преобразовать все строки: маппинг + нормализация по правилам ниже
- [ ] 4. Проверить условную обязательность; поля без источника оставить пустыми
- [ ] 5. Сгенерировать .xlsx с сохранением строк 1–2 из шаблона
- [ ] 6. Провалидировать: `python .cursor/skills/dsp-data-transform/scripts/validate.py output.xlsx`
- [ ] 7. Исправить ошибки преобразования; отсутствующие у партнёра данные — только в отчёте
```

## Шаг 1. Анализ входных данных

1. Определи формат: `.xlsx`, `.csv`, `.tsv`, JSON и т.д.
2. Найди строку заголовков (может быть не первой — проверь первые 5–10 строк).
3. Зафиксируй:
   - имена колонок и 2–3 примера значений;
   - период/гранулярность (по дням, по креативам, по кампаниям);
   - валюту суммы и признак НДС, если указаны;
   - уникальные значения для полей-справочников.

Если колонка входного файла не имеет однозначного аналога — **не угадывай**. Зафиксируй неоднозначность и спроси пользователя или пометь строку для ручной проверки.

## Шаг 2. Маппинг колонок

Составь таблицу соответствия перед преобразованием:

| Колонка шаблона | Источник (файл партнёра) | Трансформация |
|-----------------|--------------------------|---------------|
| ERID | … | as-is / из URL / … |
| … | … | … |

Типичные синонимы входных полей (не исчерпывающий список):

| Шаблон | Возможные названия у партнёра |
|--------|-------------------------------|
| ERID | erid, token, creative_token, ad_token, маркировка |
| Номер изначального договора | contract_number, agreement_no, договор |
| Дата изначального договора | contract_date, agreement_date, дата договора |
| Заказчик | advertiser, client, customer, customer_name, рекламодатель |
| **ИНН заказчика (I)** | **customer_inn**, advertiser_inn, client_inn, customer_tax_id, inn_advertiser, ИНН заказчика, ИНН рекламодателя |
| Исполнитель | publisher, contractor, executor, contractor_name, исполнитель |
| **ИНН исполнителя (N)** | **contractor_inn**, publisher_inn, executor_inn, contractor_tax_id, inn_contractor, ИНН исполнителя |
| Показы | impressions, views, показы |
| Сумма | spend, cost, amount, расход, сумма |

**Важно: ИНН заказчика и ИНН исполнителя — разные поля.** Никогда не маппить одну колонку `inn` / `tax_id` / `ИНН` на оба поля сразу.

Если во входном файле одна колонка `inn` без уточнения роли:
1. Если рядом есть `advertiser` / `customer` → маппинг на `customer_inn` (I).
2. Если рядом есть `publisher` / `contractor` → маппинг на `contractor_inn` (N).
3. Если роль **неясна** — **skip** колонку `inn` целиком; зафиксируй вопрос пользователю.

В промежуточной структуре данных используй **разные ключи**:

| Ключ | Колонка шаблона |
|------|-----------------|
| `customer_inn` | I — ИНН заказчика |
| `contractor_inn` | N — ИНН исполнителя |

## Шаг 3. Преобразование и нормализация

Для **каждой** входной строки обрабатывай **только поля с данными**:

1. Найди источник по маппингу (шаг 2).
2. Если значение пустое — **skip** (шаг 3 не выполняется для этого поля).
3. Если правило нормализации есть — примени его.
4. Запиши результат в соответствующую колонку A–S.

### Даты (колонка C)
- Формат: `YYYY-MM-DD` или `DD.MM.YYYY` (как в исходном шаблоне партнёра — привести к одному виду).
- Невалидные даты — ошибка валидации.

### Числа (R — Показы, S — Сумма)
- **Показы**: целое неотрицательное число.
- **Сумма**: число в **рублях**, разделитель дробной части — точка или запятая (нормализовать к числу).
- Убрать пробелы-разделители тысяч, символы валют.

### Справочники (D, E, F, G, L, Q)
Принимаются **английские коды или русские названия** из списка в [reference.md](reference.md).

**Внимание:** код `Distribution` встречается и в E (предмет договора), и в F (вид деятельности) — с **разным** русским смыслом. Маппинг всегда по **целевой колонке**, не по коду alone.

При маппинге:
1. Сначала ищи точное совпадение с допустимым значением.
2. Затем — нечёткое (регистр, пробелы, скобки).
3. Если значение не из списка — ошибка; не подставляй «похожее» и не выбирай ближайший вариант.

### Типы контрагентов (G, L)
Допустимые значения: `LegalPerson`, `IndividualEntrepreneur`, `PhysicalPerson`, `ForeignPhysicalPerson`, `ForeignLegalPerson` (или русские эквиваленты из справочника).

Если тип не указан во входе — **оставь пустым**, не определяй по ИНН и не угадывай.

### Включая НДС (Q)
Только: `yes` или `no` (или явные русские формулировки «с НДС» → `yes`, «без НДС» → `no`).

Если признак НДС не указан — **оставь пустым**, не предполагай `yes` или `no`.

## Шаг 4. Условная обязательность

Перед выводом проверь для **каждой строки**:

**Заказчик (I, J, K):**
- `LegalPerson` / `IndividualEntrepreneur` / `PhysicalPerson` → **ИНН (I) обязателен**
- `ForeignPhysicalPerson` / `ForeignLegalPerson`:
  - если **ИНН (I) пуст** → **Рег.номер (J) обязателен**
  - если **Рег.номер (J) пуст** → **ИНН (I) обязателен**
  - **ОКСМ (K) обязателен** всегда для иностранных типов

**Исполнитель (N, O, P):** — те же правила, что для заказчика.

Проверка обязательности нужна для **отчёта и валидации**. Отсутствующие данные **не дополняй** — оставь ячейку пустой и сообщи пользователю, какие поля не хватает.

## Шаг 5. Генерация выходного файла

```python
import openpyxl
from shutil import copyfile

TEMPLATE = "Шаблон загрузки данных от DSP (2).xlsx"
OUTPUT = "output_dsp_upload.xlsx"

def has_value(val):
    if val is None:
        return False
    if isinstance(val, float) and val != val:
        return False
    return str(val).strip() != ""

def write_cell(ws, row, col, value):
    if has_value(value):
        ws.cell(row, col, value)
    # иначе skip — ячейку не трогаем

copyfile(TEMPLATE, OUTPUT)
wb = openpyxl.load_workbook(OUTPUT)
ws = wb["Sheet1"]

COLUMNS = {
    "erid": 1,
    "contract_no": 2,
    "customer_inn": 9,
    "contractor_inn": 14,
    # ... остальные ключи → колонки A–S
}

start_row = 3
for i, record in enumerate(records):
    row = start_row + i
    for key, col in COLUMNS.items():
        write_cell(ws, row, col, record.get(key))

wb.save(OUTPUT)
```

Правила:
- **Skip пустых:** `write_cell` вызывается только для непустых значений.
- Не меняй строки 1–2.
- Одна строка входных данных (обычно) = одна строка шаблона. Если у партнёра агрегированные данные — не агрегируй без явного указания пользователя.
- Сохраняй порядок колонок A–S как в шаблоне.

## Шаг 6. Валидация

```bash
python .cursor/skills/dsp-data-transform/scripts/validate.py output_dsp_upload.xlsx
```

Исправь ошибки **преобразования** (неверный формат, опечатка в справочнике, неверный маппинг). Ошибки из‑за **отсутствия данных у партнёра** (skip) не исправляй подстановкой — перечисли в отчёте. Файл может не пройти валидацию — это ожидаемо при неполных данных.

## Шаг 7. Отчёт пользователю

После конвертации сообщи (даже если валидация не прошла из‑за skip):
1. Путь к выходному файлу.
2. Количество строк данных.
3. Маппинг колонок (кратко).
4. Предупреждения: неоднозначные поля, **пустые поля без источника**, пропущенные строки.
5. Строки, не прошедшие валидацию (если оставлены для ручной правки).

## Частые ошибки

| Проблема | Действие |
|----------|----------|
| ERID в URL, а не отдельной колонке | Извлечь параметр `erid=` или последний сегмент пути |
| Сумма в копейках или в валюте ≠ RUB | Конвертировать / запросить курс у пользователя |
| Один договор на все строки | Дублировать B, C, D, E, F, G–P **только если** эти значения явно переданы пользователем или есть во входном файле |
| Поле пусто у партнёра | **Skip** — не преобразовывать, не записывать в ячейку |
| Тип контрагента не указан | Оставить пустым; перечислить в отчёте |
| Одна колонка `inn` без роли | Маппить на `customer_inn` **или** `contractor_inn` по контексту; если неясно — **skip** и уточнить у пользователя |
| ИНН заказчика перепутан с исполнителем | Проверить: заказчик = рекламодатель (customer), исполнитель = DSP/площадка (contractor) |
| Дубли ERID + период | Не дедуплицировать без указания пользователя |
